# TPEncore 市民角色與政策任務企劃

企劃版本：1.0｜日期：2026-10-25｜狀態：提案，尚未實作／發布。

本企劃取代「送書包、找地標」為主的初版方向；既有城市模型、四市色彩、政策內容與來源仍是基礎。舊案保留於 INTERACTION_PLAN.md 作為歷程。

## 1. 核心主張

**建立自己的角色，走進四座城市，從一件生活上的難事開始，體驗不同政策想處理的問題。**

不是點亮所有建築就算完成。每個任務都必須說清楚：誰遇到什麼問題、問題發生在哪個環節、政策打算介入哪裡、還有哪些限制或未知。遊戲的目的，是讓人理解、比較與持續探索；不替政治立場打分，也不把某個提案描繪成唯一解。

### 成功體驗

- 第一次：不用讀長說明，就能建立角色並完成一段有意義的生活情境。
- 一次回訪：能接續先前角色與任務，或換一種生活身分看同一座城市。
- 完整探索：能說出不同城市的生活議題與政策差異，知道去哪裡看來源及現況。
- 不玩遊戲：原有全景、政策清單、導覽與 2D 文字版始終可直接使用。

## 2. 玩家角色：外觀、生活情境與探索進度分開

### 初次建立流程，目標 30–45 秒

1. 「建立我的市民」或「先逛逛」，遊戲入口不擋網站開場與自由探索。
2. 選預設角色，調整髮型、膚色、衣服、配件；沿用目前圓潤人物風格。
3. 自選暱稱（可留空、不可與真實姓名綁定），預設「城市旅人」。
4. 主動選 1–3 個想探索的情境：通勤、租屋／居住、育兒、學習、照顧家人、工作、城市休閒、防災。可跳過、隨時修改。
5. 選起點城市，或選「從一件生活小事開始」。
6. 看到任務簡介後決定接受，不自動開始追逐或導航。

### 角色原則

- 情境是可切換的遊戲視角，不要求真實年齡、住址、家庭狀況或政治傾向。
- 不因外觀推定性別、年齡或需求；同一角色可體驗家長、通勤者、照顧者等故事。
- 輪椅等輔具應是可選的角色外觀與動線需求，非裝飾獎品；模型與路徑驗證完成後才提供，不在第一期假裝支援。
- 外觀不影響任務難度、資源或政策推薦。所有城市與任務均可手動瀏覽。
- 第一版無登入，角色與進度僅存在目前裝置的 localStorage（不使用 Cookie）；網站首次使用清楚告知，可刪除。
- 不把角色選擇傳到現有 counter；不蒐集自由輸入暱稱。跨裝置同步為後期獨立議題。
- 提供匯出／匯入進度（第二階段），匯入須檢查大小、版本與欄位，不執行內容。

### 地圖上的「我」

- 玩家為一個獨立可辨識角色，腳下有四市色的圓環；只在近景需要時顯示，遠景收起。
- 操作以「點目的地 → 沿道路走到 → 點互動」為主，不做手機虛擬搖桿。
- 可切換「跟隨角色／自由看地圖」。拖曳、旋轉、縮放立刻解除鏡頭跟隨；角色不隨相機平移而瞬移。
- 長路線可按「直接到達」；等待走路、精準操控及反應速度不作為通關條件。
- 跨城使用交通節點與短轉場，不要求徒步穿越橋梁；既有跨城政策可承接故事。

## 3. 政策內容如何轉成任務

### 一張任務內容卡的必備欄位

| 欄位 | 編輯規則 |
|---|---|
| 生活情境 | 一句可理解的生活問題；若未有調查證據，標示「情境設定」，不可宣稱是全市居民實況 |
| 參與者 | 玩家、居民、設施；居民是虛構，不冒充真實當事人 |
| 想完成的事 | 具體行為，例如安排接送與通勤，而非「了解交通政策」 |
| 痛點環節 | 時間衝突、資訊落差、轉乘、可近性、行政程序等 |
| 政策連結 | 真實 city/theme/item ID，至少一個可解析來源 |
| 互動步驟 | 3–5 步，每一步都有動作與可觀察回饋 |
| 選擇與限制 | 可有不同路徑；無來源的時間、費用、容量不給數字 |
| 結尾 | 哪一環被回應、未解決的需求、政策狀態、資料來源 |
| 體驗章 | 構想／既有措施／跨城合作；不用遊戲完成狀態代替政策進度 |
| 可用性 | 手機觸控、文字替代流程、減少動態、退出與續玩 |

### 任務與政策不是一對一

一個生活問題可以連結多個政策，一個政策也可以出現在多種角色故事中。全量政策必須能在任務圖譜中查到，但不為了湊數，讓每項政策各做一個相同的點擊任務。

覆蓋分三級：**A 可玩主線**（完整情境）、**B 支線互動**（短對話／一個環節）、**C 政策延伸**（結尾相關內容與來源）。C 不宣稱已有獨立玩法。沒有足夠資料的內容列入待補，不編造。

### 三種證據模式

- **政策構想體驗**：以「若依此構想規劃」作開場；不將提案設施畫成已營運，也不顯示虛構上路日期。
- **既有措施認識**：依有來源的任內紀錄與適用範圍設計；歷史紀錄不代表今日仍可申請，需標示資料日期與官方查詢。
- **跨城議題探索**：呈現轉乘／服務銜接等合作需求；僅在資料有記載時指稱合作機制，保留共同推動單位及來源。

## 4. 全站議題主線

| 主線 | 常見情境 | 可用互動 | 理解目標 |
|---|---|---|---|
| 到得了的城市 | 上班、上學、就醫的轉乘與接駁 | 依需求串接交通節點、比較路徑 | 路線、接駁與可近性如何相互影響 |
| 安心住下來 | 租住、老屋安全、家庭階段改變 | 看屋條件、更新流程拼圖、設施清單 | 住宅供給、資格、更新程序的差異 |
| 家庭的一天 | 臨托、接送、親子活動 | 安排日程、找對服務、交接 | 補助、名額、地點與時間是不同問題 |
| 照顧不孤單 | 長者就醫、出門、照顧壓力 | 規劃可達行程、串接照護服務 | 醫療建設、福利與照護支援的分工 |
| 學習與下一步 | 學習資源、實習、創業與技能 | 找資源、配對需求、合作小專題 | 設施／課程與就業機會之間仍有條件 |
| 平安的日常 | 豪雨、排水、風險資訊 | 檢查節點、演練資訊傳遞 | 預警、事前整備、災後補強各處理什麼 |
| 共同生活 | 文化、觀光、運動、族群與地方 | 共同安排活動、設計友善路徑 | 使用者需求可能不同，不只增加設施 |
| 城市的未來 | AI、產業園區、環境與公共建設 | 利害關係對話、階段排序、條件配對 | 執行前提、時間與跨機關合作 |

不採單一「幸福值」或「支持度」。構想性成效用定性文字呈現；如需遊戲時間單位，標示為情境單位，不能偽裝成真實政策預測。

## 6. 一個任務的完整腳本範例

**台北：臨時有事的下午**｜類型：政策構想體驗｜建議 2–3 分鐘。

1. 居民：「下午臨時有事，原本的接送安排來不及了。」玩家選「一起想辦法／稍後」。
2. 顯示三個需求卡：臨時照顧、接送距離、家庭支出。先選此次最急的一項；其他需求保留，不判錯。
3. 玩家點地圖上的「托育資訊節點」，走近後辨識臨托、固定托育與補助三張服務卡。
4. 選擇適合臨時需求的卡片，顯示該政策構想內容與原始來源；選其他卡會說明能幫上哪一環，再允許切換，不扣分。
5. 共同整理方案：「先確認可服務時段與名額，再安排接送；補助可降低支出，但不代表自動有位置。」若來源沒有細則，明列待確認。
6. 居民回應、取得「家庭生活：臨托探索」章。結尾是理解一種政策工具，不演出服務已預約成功。
7. 可選「看相關政策」「換個生活需求」「回地圖」。政策原文不要求讀完才給章，來源入口一直可見。

情境中的時間安排是敘事，不以遊戲成功率宣稱政策效益；不代辦、不收實際申請資料。

## 7. 互動系統與自由度

共用六種積木：找人對話、沿路抵達、日程安排、需求配對、節點觀察、合作交接。每個任務使用其中 2–3 種，避免全站變成「點三下領章」。

- 初次任務 60–90 秒，標準任務 2–4 分鐘，一段城市故事 8–12 分鐘；皆為設計目標，待測試調整。
- 同時只啟用一個主任務，但可中途看政策、切時間模式、回全景與離開。
- 狀態：未開始 → 已介紹 → 進行中 → 暫停／完成；退出可續玩，不強制重頭走路。
- 切城市時暫停原任務，提示「繼續／改逛這座城市」；已有的鏡頭辨識城市不自動抹掉任務。
- 對話可跳過、重看。所有選擇可回退；只有明確任務步驟推進進度，不因誤觸地圖完成。
- 按地圖空白可收起視窗，但不等於取消任務；任務目標留在可收合卡片。
- 不加飢餓、金錢倒數、體力、抽獎、付費解鎖、連續登入壓力或政治排行。

## 8. 持續參與：生活護照與跨城故事

### 三種紀錄

1. **我的角色**：外觀與可切換的生活視角。
2. **生活護照**：按「城市 × 議題」記錄已探索內容與個人收藏，不顯示政治支持度。
3. **故事足跡**：保留已遇見的居民、故事摘要、關聯政策與資料更新日期。

同一政策出現在不同故事不重複堆分；玩家完成的是不同視角的理解。徽章名稱採「探索」「認識」，避免「解決全市交通」「完成長照」等誤導。

### 回訪理由

- 同一痛點可換角色視角，不靠每天隨機重複任務。
- 新增真實政策資料或來源後，對相關故事標示「內容有更新」，讓玩家自選重訪。
- 完成兩市相關故事可開啟跨城篇，例如生活中的轉乘與照顧銜接；前兩個分階段任務無硬性解鎖門檻。
- 第二期才考慮本機產生分享卡；預覽、下載或分享均由玩家主動操作，不公開真實姓名或進度識別碼。
- 不先做多人連線。後期如加入合作，先設計兩位虛構居民的接力，避免帳號、聊天及同步成本蓋過內容體驗。

## 9. 畫面與操作規格

### 入口

右上角沿用既有工具，新增一個「我的市民」入口，內含角色／任務／護照。初期不增加三個常駐按鈕。原政策探索是預設瀏覽模式，遊戲提示需主動啟用。

### 手機

- 接任務前簡短底部卡，進行中一行目標＋展開／帶我過去，卡片避開瀏覽器安全區與既有頁尾。
- 近景最多 3 個居民互動提示；任務只顯示下一個目標，不與整批政策標牌一起搶版面。
- 主操作區至少 44×44 CSS px；不要求拖曳、小角色精準點選或一邊旋轉一邊操作。
- 政策詳細、導覽卡、任務卡同時最多一張展開；其他保留狀態，不相互清除。

### 電腦

- 任務卡在側邊，與政策抽屜共用面板管理；3D 地圖仍是主要視覺。
- 可用鍵盤選任務及步驟，焦點可見。彈窗關閉後回到原觸發點。

### 可近性與效能

- 文字版任務可用同一步驟完成，不必依靠 3D 找物、顏色或動畫；來源與結尾相同。
- 尊重減少動態與音樂開關，不自動播放新音效；天氣／日夜不影響任務可完成性。
- 僅新增一個玩家模型、當前任務的少量拾取區；保持既有 NPC 批次與遠景簡化。
- 與現有全景 5 秒運鏡互斥：任務展開／跟隨時不啟動；玩家操作優先。

## 10. 資料與程式架構草案

不把腳本直接散寫在 ui.js。提案分層如下（檔案尚未建立）：

- `data/missions/*.json`：情境、步驟、分支、引用、覆蓋級別與編輯狀態。
- `3d/player.js`：外觀、角色世界座標、道路尋路與跟隨。
- `3d/missions.js`：狀態機、條件判斷、事件去重與任務恢復。
- `3d/mission-ui.js`：任務／護照／角色介面，統一面板優先順序。
- 共用政策解析器：由 ID 取得目前文字、狀態、來源；任務不自行複製成第二份事實庫。
- 本機存檔含 schemaVersion、角色設定、missionId/stepId、已探索節點；不保存原始政策全文，不將任意 HTML 寫回畫面。
- 內容版本改動時保留已獲探索章，必要時只重置受影響步驟並提示；儲存不可用時允許當次訪問繼續。
- 既有 PHP counter 保持單一瀏覽累計，資料庫不新增玩家檔案；本企劃不等同啟用行為分析。

### 編輯流程與追溯

政策盤點 → 敘事情境草稿 → ID／來源映射 → 互動腳本 → 事實與狀態複核 → 手機原型 → 可近性／效能驗證 → 發布。

建置檢查必須攔下不存在的 city/theme/item/source、缺少結尾／退出、無法抵達的步驟。來源撤下或政策改版時，相關任務應暫停或退回「待複核」，不能繼續呈現舊承諾。

`POLICY_MISSION_INVENTORY.json` 是本次從現有四市政策檔與政績資料產生的規劃盤點。涵蓋尚未編寫任務的內容，所有列初始均是「待腳本」，**不是已確認痛點、已完成引用覆蓋或上線任務數**。政績若無穩定 ID，以來源檔案＋陣列位置暫作定位，實作前建立穩定 ID 並處理可能重複。

## 12. 驗收與成效判斷

### 必須通過

- 四市政策條目都有盤點位置；首批 8 任務每市 2 個，皆有情境、限制、正確引用、退出、續玩與文字替代。
- 未公布的路線、細則、時間、容量與預算不假造；遊戲完成永遠不改政策進度。
- 角色儲存、停用儲存、重新整理、城市切換、政策窗、導覽、全景、音樂、日夜及資料版本變更皆可恢復或安全退出。
- 320px 手機、桌機、鍵盤、減少動態與目前 NAS 部署方式都可用；原有自由探索入口不退化。
- 先記錄既有手機效能基準；新玩法不得造成持續掉幀或記憶體隨重玩增長，超標則減模型／提示／動畫後再驗收。

### 先驗證理解，再看停留

- 小規模可用性測試先找 5–8 人，觀察是否能不靠引導建立角色、完成任務、說出一項政策作用及一項限制。
- 初始目標：至少 80% 受測者可完成首任務，至少 70% 能辨認遊戲結果與政策現況不同。樣本小，只用來修正設計，不宣稱代表所有使用者。
- 後續才考慮匿名累計：任務啟動／完成、相關政策開啟、來源點擊；不把暱稱、情境選擇或角色外觀送出。
- 若採行為統計需另行規劃端點、重試與去重，以及必要的說明；尚未啟用。現有無 Cookie counter 無法提供留存率、不重複玩家或可靠停留時間。
