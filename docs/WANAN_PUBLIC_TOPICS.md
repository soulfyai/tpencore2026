# 公開「大家在聊什麼」頁面提案

2026-10-30（Asia/Taipei）。使用者希望每日話題彙整對大眾公布。
此文件只有提案，尚未建置公開統計頁、蒐集聊天、啟用摘要排程或公開個案。

## 建議位置

- 政策選單加入「大家在聊什麼」，連至獨立資訊頁，避免讓3D地圖多一個常駐視窗。
- 首頁新增可收合的小摘要卡：最新統計日期、前三個話題與「看完整五大話題」連結。
- 聊天結束時可提供同一入口，但不每次回覆插入推廣。
- 第一版先做獨立預覽，正式站位置與發布另行確認，不能本輪就改正式四頁。

## 公開內容

每日台北時間09:00公布前一天的經審閱摘要，頁首明確寫統計區間與更新時間。
每題只顯示標題、2～3句主要訴求、不同對話數、訊息數，以及資料足夠時的七日趨勢。
另設近七日／近三十日，區分建言、問題反映及政策詢問；一般閒聊不混入市政排行榜。
同一對話同一話題每日只計一次。不同對話數不等於不同人數，也不是全體市民民調。
少於五題只顯示現有題數，沒有資料就顯示「尚無可公布摘要」，不造測試排名。

呈現句型示意（非真實統計）：
「公車等候與班距：部分參與對話希望尖峰班次更穩定，並改善到站資訊。」
不放具體示範數字，避免誤認為實際蒐集結果。

## 公開前審閱與保護

- 取得清楚的資料用途告知與參與同意，再將去識別文字納入分析；不同意仍可聊天。
- 公開摘要不顯示原始聊天、電話、姓名、精確地址、帳號、對話ID或足以辨認個人的例句。
- 敏感或極少量話題預設不公開；建議至少五個不同對話才考慮上榜，但這個門檻不保證不同人數或完全匿名，仍需人工檢查與灌水排除。
- 描述「用戶反映」而不是宣告事件已核實，不點名未經查證的被指控對象；涉及個案者轉為一般議題或不公開。
- AI先生成草稿，由管理者審閱後發布。審閱未完成就保留上一版，標示日期，不假裝每日自動通過。
- 保留更正／移除入口及版本紀錄；刪除來源資料後重算受影響統計，避免繼續留下可辨認資訊。
- 清楚註記：「本站聊天參與者的意見彙整，不代表全體市民；非正式陳情受理紀錄。」
- 不公開政治支持傾向、不製作個人政治檔案、不將聊天統計包裝成選情民調。

## 建議實作順序

1. 先確認公開頁位置、審閱人與公開門檻，製作只含明確合成資料的獨立UI預覽。
2. 再建內部管理頁、同意流程、去識別保存與分類，測試刪除、灌水、少量資料、時區和權限。
3. 真實資料驗證後，才另行核准公開頁與每日排程；管理端必須登入，公開端只讀已審核彙總。

保存期限初步建議延續聊天專案提案：去識別訊息30天、每日彙總90天，需定案後才能啟用。
