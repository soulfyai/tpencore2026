# 政策市每日政策查核與發布

使用者於2026-11-04（台北時間）要求政策每日查核，並已同意修復正式網站更新。此專用流程可自動更正政策主庫及發布tpencore2026/main；不改人物、美術、網站設定、計數、秘密或其他專案功能。新聞每日流程仍只更新新聞庫；不可將新聞入庫當政策已查核。本流程毋須人工逐次核准。

## 每輪作業

1. 用GitHub工具讀取本repo最新main、HANDOFF.md、本文件，以及wanan_digitwin/feature/chatbot-core的AGENTS.md。保留其他開發者變更，讀取最新branch head，發布用expected_sha，不force；並行更新須重讀、合併及測試。網站沿既有開發分支→main正常fast-forward流程；聊天只更新feature/chatbot-core及test/local-web-package，不合併聊天main或PR。
2. 讀取prototypes/v044-art-data.json及data/policy-audit/current.json，逐項列出穩定ID。當前台北62項、新北56項；以實際清單為準，不預設參選人名單。優先續查待查項目，再核對其他政策的原始發布、現行申請辦法、預算／議會文件及實施進度，並搜尋最近24小時更新。原文必須實際開啟讀取，搜索摘要、HTTP200或雜湊均不能冒充AI事實核對。
3. 分開辨認：誰提出何主張、政策承諾、研議、已實施措施、成效說法。來源僅支持曾有此承諾時，不宣稱目前已落實；歷史統計標日期及歸屬，不當作今日成效。指控、未證實說法保留發言者及其他方回應。查無最新文件即如實待查，不捏造。
4. 建立data/policy-audit/YYYY-MM-DD.json，並更新current.json，日期採Asia/Taipei及真實含時區時間。schema_version=1，audit_date、checked_at、note、baseline_source、new_sources、overrides、entries。entries必須一對一涵蓋全部項目ID，含id/city/status/checked_at/note/evidence/verification_scope；狀態為verified_updated、verified_unchanged、needs_followup、source_unavailable、not_checked。只有完成原文判讀才用verified；可只證實原發布，但note須明示驗證範圍，不等同獨立驗證成效。
5. evidence每來源保存url、method:source_pages_read、read_at（真正判讀時間）、finding（具體支持／不支持哪個說法）；可附accessed_at（HTTP取回時間）與body_sha256，不存全文。verified的checked_at不得早於read_at或超前本輪。不能批次將下載成功直接改成verified。來源date是發稿日期，生效日、更新日或未知不能冒充發稿日；未知用null。
6. 更正僅限plain/facts/phase/contentKind/sources，放在當日entry.changes且status=verified_updated；穩定ID不變。無新證據保留原內容並標待查。新增來源用不衝突ID含city/id/url/title/publisher/date/checkedAt/tier，tier為official/news/interview。
7. **保留歷史更正**：新一輪overrides必須合併前輪overrides及前輪各entry.changes（同ID較新欄位優先），new_sources也累積保留，不可因隔日未再修改而回復舊錯誤。當日entry.changes只放本輪更正，歷史YYYY-MM-DD.json不能覆寫成新一天。保留舊查核時間不計入今日完成度。既有baseline CHECKED_AT保留，不能只改日期冒充作業。
8. 執行`PYTHONPATH=tools python -c 'from policy_audit import prepare; prepare()'`更新production JSON，並`python -m unittest discover -s tests -v`。完整`python tools/package_site.py`建置會在所有預覽產生器之後重套覆核，避免重新建置覆蓋更正；再執行測試，失敗停止發布。commit包含ledger、production JSON及必要程式／文件，逐項更正有來源可追查；不順便改無關資料。
9. 網站發布後確認GitHub Actions成功、Pages version.json及正式https://tpencore.tw/version.json的commit相符，並核對四個正式HTML SHA256（index.html/index3d.html/2d.html/chiang-wan-an.html）。沿用NAS固定檔案排程，不修改NAS本地設定或秘密。頁面分開顯示政策查核進度、未核實的舊資料基準與新聞日期；台北頁只計台北，雙市清單計全部。未同步不能說已上線。
10. 用聊天repo tools/import_tpencore.py由本次**已提交**production JSON匯入data/tpencore_taipei.json，--commit填網站來源commit，保留資料指紋。只有原文核對成功者有逐項checkedAt；pending保留policyAudit限制，不蓋全庫checkedAt。新聞curated.sqlite3及語錄不因政策作業改寫。執行聊天repo全部unittest後提交feature/chatbot-core，再用tools/build_local_bundle.py固定清單發布test/local-web-package，提交標題`本機試聊包：<source_sha>`；保留既有二進位與其他允許檔。
11. GET https://chat.tpencore.tw/api/data/status，比對policies.sha256與發布的data/tpencore_taipei.json位元組SHA256，查看latest_item_checked_date、verified_count及pending_count。/health與排程建立不證明政策資料更新。任一階段失敗保留舊發布並明列研究、資料更正、GitHub、網站NAS、聊天NAS的成功／待同步／失敗，不能以摘要或排程代替本輪入庫成果。
